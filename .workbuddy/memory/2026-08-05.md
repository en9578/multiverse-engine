## 补充设计：对话存储 + 上下文隔离

用户指出架构图还缺「对话存储」，且不做好隔离会造成上下文污染。补充设计如下（承接 2026-08-03 工程现状检索）。

### 隔离维度（防污染核心）
按 `taskId + universeId + sessionId` 三级隔离：
- taskId：不同卖家任务绝对隔离
- universeId：同任务内宇宙 A 对话不串入宇宙 B 推演（关键——用户穿越多宇宙追问时，R1 调用只能带当前宇宙上下文）
- sessionId：同宇宙多次会话隔离

### 对话存储
- `conversation` 表：id / task_id / universe_id / session_id / role(user/assistant/system) / content / gmt_create
- MySQL 持久 + Redis 热缓存（key: `ctx:{taskId}:{universeId}:{sessionId}`）

### ContextManager（隔离闸门）
- 调 R1/Qwen 前按三级隔离查 conversation，只组装当前域对话
- 超 token：系统提示 + 最近 K 轮 + 早期轮次 Qwen 摘要压缩
- DAO 强制 WHERE 隔离过滤（不带过滤不让查，防呆）

### 防污染保障
- BailianManager 调用 requestId 含 taskId+universeId
- 日志带 taskId+universeId，串上下文可追溯
- 单测覆盖跨任务/跨宇宙 context 不串（关键用例）
